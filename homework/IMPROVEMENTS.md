# Улучшения MVP

Направления развития сверх базового MVP. Для каждого: зачем, какие файлы меняются,
как проверить. Отмечено, что **реализовано** в этом репозитории.

## ✅ 1) Оценка качества (Eval) — РЕАЛИЗОВАНО

- **Зачем:** вместо ручной проверки demo-вопросами — объективные метрики retrieval.
- **Что сделано:** `scripts/eval_retrieval.py` — 10 эталонных вопросов с ожидаемой
  группой (`category`), считаются `hit@k` и `MRR`. Соответствие чанк→группа берётся
  из `datasets.json`.
- **Файлы:** `scripts/eval_retrieval.py`, тест `tests/test_extra.py`.
- **Как проверить:** `uv run python scripts/eval_retrieval.py` → текущий результат
  `hit@5 = 1.00`, `MRR = 0.95`.

## ✅ 2) Улучшение интерфейса Streamlit — РЕАЛИЗОВАНО

- **Зачем:** диагностика и удобство — видеть, что попадает под порог, и почему.
- **Что сделано:** ползунок порога `min_score`, выбор `top-k`, **подсветка** совпавших
  слов запроса в фрагментах, пометка фрагментов ниже порога.
- **Файлы:** `app/main.py`, `app/textutils.py` (+ тесты подсветки).
- **Как проверить:** запустить UI, подвигать порог — список источников и ответ меняются;
  слова запроса выделены `<mark>`.

## ✅ 3) Качество retrieval (TF-IDF tuning) — РЕАЛИЗОВАНО

- **Зачем:** базовый `TfidfVectorizer()` ловит много шумовых слов.
- **Что сделано:** english stop-words, n-граммы (1,2), `min_df=2`, `max_df=0.9`,
  `sublinear_tf=True` в `scripts/build_index.py`.
- **Как проверить:** сравнить `eval_retrieval.py` до/после (hit@k вырос).

## Направления на будущее (не реализованы)

### 4) Embeddings вместо TF-IDF
- Поиск по смыслу (sentence-transformers). Меняется `build_index.py` (считает эмбеддинги)
  и `retriever.py` (ближайшие векторы). Проверка — рост hit@k на синонимичных запросах.

### 5) Векторная БД
- ChromaDB / Qdrant / FAISS для быстрого поиска по большим коллекциям. Меняется слой
  хранения и сборки индекса.

### 6) Hybrid search
- Комбинировать lexical (BM25/TF-IDF) + semantic (embeddings). Меняется `retriever.py`
  (объединение ранжирований). Проверка — eval на «трудных» запросах.

### 7) Reranking
- Cross-encoder пересортировывает top-k кандидатов. Доп. шаг между retrieval и ответом.

### 8) Подключение LLM
- OpenAI-совместимый API или локальная модель вместо сборки ответа из чанков. Меняется
  `generator.py` и формат контекста/промпта. Контекст уже готов в `format_sources`.

### 9) Данные и автообновление
- Версионирование корпуса, автоматическая пересборка. Меняется data-pipeline.
