# 00 · Идея проекта

## Проблема

Нужно научиться строить RAG (Retrieval-Augmented Generation) с нуля и понимать
**каждый шаг** — от сырых данных до ответа со ссылками на источники.

## Идея

Мини-RAG поверх корпуса коротких тематических текстов. Пользователь задаёт вопрос —
система находит релевантные фрагменты, показывает их (с `doc_id` и score) и
формирует ответ **только по найденному контексту**. Если ничего релевантного нет —
честный **отказ**, без выдумок.

## Целевые данные

[20 Newsgroups](http://qwone.com/~jason/20Newsgroups/) — ~18000 постов из 20 тематических
групп Usenet (наука, спорт, политика, техника, религия). Открытый, легко скачивается
через scikit-learn, не требует ключей. Для MVP берём сбалансированную выборку 1200 постов.

Почему этот датасет:
- 20 разных тем → легко придумать и рабочие, и negative-вопросы;
- наличие меток группы (`category`) → можно автоматически измерять качество retrieval;
- объём 1000+ записей → уровень «отлично» по критериям задания.

## Ценность

- **Учебная:** прозрачный pipeline, который повторяет структуру образца
  [MaratNotes/rag-tutorial](https://github.com/MaratNotes/rag-tutorial), но на других данных.
- **Практическая:** шаблон, в который легко подставить свои тексты.

## Что НЕ делаем в MVP

- внешние LLM и embeddings (только TF-IDF);
- векторные БД (индекс — файлы на диске);
- авторизацию, многопользовательский режим, деплой.

## Критерий успеха MVP

3 рабочих demo-вопроса с ответом и источниками + 1 negative-вопрос с отказом,
зелёные тесты, запуск по README на чистой машине.
